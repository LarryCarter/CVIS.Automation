# Base Automation Test Classes

# Purpose

This folder contains the official non-browser CVIS automation base classes.

# Responsibilities

- Define the canonical non-browser NUnit lifecycle owner.
- Provide API-specific setup through `BaseAutomationCvisApiTest`.
- Provide database-specific helpers through `BaseAutomationCvisDatabaseTest`.
- Preserve temporary compatibility aliases for old base class names.

# When to use

Use this folder when choosing the correct base class for a non-browser test.

| Test type | Use |
|---|---|
| Normal NUnit automation, no browser | `BaseAutomationCvisTest` |
| API automation | `BaseAutomationCvisApiTest` |
| Database automation | `BaseAutomationCvisDatabaseTest` |

# When NOT to use

Do not use these base classes for browser tests. Browser tests belong under `CVIS.Playwright.NUnitCompat/Base`.

# Architecture

Only `BaseAutomationCvisTest` owns these NUnit lifecycle attributes:

```csharp
[OneTimeSetUp]
[SetUp]
[TearDown]
[OneTimeTearDown]
```

Specialized base classes must override lifecycle hooks instead:

```csharp
OnFixtureSetUpAsync
OnTestSetUpAsync
OnTestTearDownAsync
OnFixtureTearDownAsync
```

Reason: NUnit can run multiple setup and teardown methods across inheritance, but that creates confusing ordering and duplicate lifecycle behavior. One NUnit lifecycle owner makes execution predictable.

# Examples

API test:

```csharp
public sealed class PlatformApiTests : BaseAutomationCvisApiTest
{
    [Test]
    public async Task Platforms_ShouldReturnSuccess()
    {
        var result = await ApiClient.GetJsonAsync<object[]>("/platforms");
        Assert.That(result, Is.Not.Null);
    }
}
```

Database test:

```csharp
public sealed class DatabaseSmokeTests : BaseAutomationCvisDatabaseTest
{
    [Test]
    public async Task Database_ShouldOpen()
    {
        await AssertDatabaseConnectionCanOpenAsync();
    }
}
```

# Common mistakes

- Creating domain base classes such as `PolicyDriftBaseTest`.
- Using the lifecycle report as the authoritative test count.
- Adding Playwright imports here.
- Adding NUnit lifecycle attributes to specialized base classes.

# Reporting note

Lifecycle reporting is not the authoritative test count.

Lifecycle logs are useful for debugging setup and teardown behavior, but real test totals come from:

```text
TestResults\TRX
TestResults\NUnitXml
```

The authoritative HTML report is generated by `CVIS.Playwright.Reporting.Tool` and written to:

```text
TestResults\CPN\cpn-report.html
```

Do not confuse these:

| File | Meaning |
|---|---|
| `cpn-report.html` | authoritative all-tests report |
| `cpn-lifecycle-report.html` | diagnostic lifecycle report only |
